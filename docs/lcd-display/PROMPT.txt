Add the LCD torque-readiness display for the smart glove. Everything you need is in docs/lcd-display/ (I copied it in from another machine; it is not committed yet). Read docs/lcd-display/README.md, SPEC.md and PROTOCOL.md first, plus CLAUDE.md for the repo's safety rules.

0. Make sure you are on main and it is up to date (`git checkout main && git pull`). Create a new branch `feat/lcd-display` from it.
1. Copy docs/lcd-display/backend/lcd_bridge.py to backend/app/lcd_bridge.py and docs/lcd-display/backend/test_lcd_bridge.py to backend/tests/test_lcd_bridge.py. Remove the "Copy to ..." line from the top of each copied file's docstring.
2. Apply the hooks: `git apply docs/lcd-display/backend/main.py.patch`. If it does not apply cleanly because main.py moved, make the same three edits by hand: (a) in lifespan, start `lcd_bridge.run(lambda: sim.stopped)` as a task when `lcd_bridge.enabled()` and cancel it on shutdown; (b) in `/api/hardware/status`, call `lcd_bridge.record_reading(reading)` before returning it; (c) in `/api/hardware/torque/enable`, call `lcd_bridge.torque_started()` before `enable_torque` and `lcd_bridge.torque_finished(error_text_or_None)` on every exit path.
3. Set up the backend if needed (`cd backend && python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`, or `.venv\Scripts\activate` on Windows), then run `python -m pytest -q`. Everything must pass. If test_vision fails only because cv2/OpenCV is missing, install it or report it as environment-only; do not change vision code. The bridge is off unless HANDOFF_LCD_PORT is set, so the tests never open a port.
4. Keep the firmware at docs/lcd-display/firmware/handoff_lcd/handoff_lcd.ino as is (I flash it from the Arduino IDE). Only change it if the spec and the code disagree, and tell me.
5. Add a short "LCD display" section to README.md that points to docs/lcd-display/WIRING.md and documents HANDOFF_LCD_PORT.
6. Rules: the bridge must never scan servos itself, open the servo controller port, or call any motor-write function; tests/test_lcd_bridge.py checks this. Never set HANDOFF_ENABLE_HARDWARE_WRITES for testing, and do not touch any /api/hardware/* write behaviour beyond the two lcd_bridge calls in the torque route.
7. Commit docs/lcd-display/ (all of it, including this PROMPT.txt), the two new backend files, the main.py change and the README edit on `feat/lcd-display`. Push it and open a PR into main with `gh pr create`. Do not merge it. Report the PR link and the test output.
